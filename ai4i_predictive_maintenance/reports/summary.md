# Day 1 数据理解总结

本项目基于 AI4I 2020 工业数据集，对设备故障影响因素进行分析，并在后续阶段建立基础预测模型，为预测性维护提供参考。

## 数据集是干什么的

这个数据集记录了工业设备在不同运行状态下是否发生故障。每一行可以理解为一条设备运行记录，每一列描述这条记录的产品信息、运行状态或故障情况。

## 目标字段

目标字段是 `Machine failure`。

- `1` 表示发生设备故障。
- `0` 表示没有发生设备故障。

## 主要特征

| 字段名 | 中文含义 | 业务意义 | 类型 |
|---|---|---|---|
| `UDI` | 唯一记录编号 | 区分每条记录，不直接代表设备状态。 | 编号字段 |
| `Product ID` | 产品编号 | 追踪产品身份，通常不是核心故障规律字段。 | 类别/文本字段 |
| `Type` | 产品类型 | 不同产品类型可能有不同故障风险。 | 类别字段 |
| `Air temperature [K]` | 空气温度 | 设备周围环境温度，可能影响散热。 | 数值字段 |
| `Process temperature [K]` | 工艺温度 | 加工过程温度，可能反映设备运行热状态。 | 数值字段 |
| `Rotational speed [rpm]` | 转速 | 旋转部件每分钟转动次数，反映运行速度。 | 数值字段 |
| `Torque [Nm]` | 扭矩 | 设备运行时承受的力矩，反映负载大小。 | 数值字段 |
| `Tool wear [min]` | 刀具磨损时间 | 刀具使用或磨损时间，可能影响故障风险。 | 数值字段 |
| `Machine failure` | 是否发生设备故障 | 后续预测性维护分析的核心目标字段。 | 目标字段，0/1 |
| `TWF` | 刀具磨损故障 | 是否因刀具磨损导致故障。 | 故障原因标记，0/1 |
| `HDF` | 散热故障 | 是否因散热异常或热量无法有效释放导致故障。 | 故障原因标记，0/1 |
| `PWF` | 功率故障 | 是否因功率状态异常导致故障。 | 故障原因标记，0/1 |
| `OSF` | 过载故障 | 是否因过载或应力过大导致故障。 | 故障原因标记，0/1 |
| `RNF` | 随机故障 | 随机性故障，可能不容易由当前字段解释。 | 故障原因标记，0/1 |

## 后续分析方向

1. 整体故障率是多少？
2. 不同产品类型的故障率是否有差异？
3. 刀具磨损越高，故障率是否越高？
4. 温度、转速、扭矩和故障是否存在明显关系？
5. 各故障类型的分布如何？

## 易混淆提醒

- `Machine failure` 是总故障标记，`TWF/HDF/PWF/OSF/RNF` 是具体故障原因标记。
- `Air temperature [K]` 是环境空气温度，`Process temperature [K]` 是工艺过程温度。
- `Rotational speed [rpm]` 表示转得多快，`Torque [Nm]` 表示用力多大。
- `Product ID` 是产品编号，`Type` 是产品类型。

## Day 2 数据质量检查总结

Day 2 主要完成基础数据质量检查。当前数据集共有 10000 条记录、14 个字段，缺失值总数为 0，完全重复行数量为 0，说明数据整体结构较完整，适合进入后续探索性分析。

总故障标签 `Machine failure` 存在明显类别不平衡：非故障样本 9661 条，故障样本 339 条，故障率约为 3.39%。这符合工业设备故障低频发生的特点，但后续分析和建模需要重点关注故障样本识别能力，不能只看整体准确率。

产品类型 `Type` 分布不均衡：`L=6000`、`M=2997`、`H=1003`。后续比较不同产品类型风险时，应比较各类型内部故障率，而不是只比较故障数量。

五类故障原因 `TWF/HDF/PWF/OSF/RNF` 都是稀疏事件，计数分别为 `46`、`115`、`95`、`98`、`19`。解释具体故障原因时需要谨慎，避免基于少量样本做过强结论。

下一步建议进入基础 EDA：围绕整体故障率、产品类型差异、刀具磨损、温度、转速、扭矩与故障之间的关系做单变量和双变量分析。

## Day 3 第一轮 EDA 图表分析总结

Day 3 开始进入第一轮 EDA，主线仍以总故障标签 `Machine failure` 为核心。由于 Day 2 已经发现总故障率约为 3.39%，且具体故障类型字段较稀疏并与总标签存在少量不完全一致记录，因此本轮暂不深入拆分具体故障原因，而是先观察产品类型和关键运行变量与总故障之间的关系。

第一轮图表显示，`Machine failure` 存在明显类别不平衡，故障样本数量远少于非故障样本。`Type` 样本量分布也不均衡，因此比较产品类型风险时应看各类型内部故障率，而不是只看故障数量。当前 `L` 类型故障率约为 3.92%，高于 `M` 和 `H`，后续值得进一步分析。

刀具磨损与故障存在较明显相关迹象。按磨损区间分箱后，`Tool wear [min]` 超过 200 分钟的样本故障率明显升高到约 15.49%。此外，故障组相比非故障组表现为平均扭矩更高、平均转速更低、平均刀具磨损更高，说明这些运行状态变量可能与设备异常负载或故障风险有关。

本轮 EDA 的结论仍属于相关性观察，不能直接解释为因果关系。下一步建议继续做更系统的双变量分析、异常值检查和相关性分析，为后续特征工程和基线建模做准备。

## Day 4 MySQL 工作流与 SQL 资产整理总结

Day 4 的目标是将已经在 MySQL Workbench 中成功导入的 `predictive_maintenance2020.ai4i2020` 表脚本化、校验化，并纳入 VSCode 工作流管理。今天不重新执行 GUI 导入，而是把数据库验证、建表记录、基础分析查询和可复用视图整理成项目中的 SQL 资产。

`sql` 目录已调整为更清晰的顺序：`01_create_database_and_table.sql` 用于保存数据库和表结构定义，并记录 `SHOW CREATE TABLE predictive_maintenance2020.ai4i2020;` 的使用方式；`02_check_import.sql` 用于导入后校验，包括总行数、前 10 行预览、`Type` 分布、`Machine_failure` 分布、故障类型计数、产品类型故障率、刀具磨损分箱故障率和标签一致性检查；`03_basic_analysis.sql` 用于沉淀可重复执行的基础 SQL 分析；`04_views.sql` 用于创建后续可复用的分析视图。

## Day 5 SQL 业务分析总结

Day 5 的目标是让 SQL 真正参与业务分析，而不只是承担数据导入和校验功能。本阶段将 `sql/03_basic_analysis.sql` 整理为固定口径的 SQL 分析脚本，用 MySQL 复现并扩展 pandas / EDA 阶段观察到的关键现象。

本次 SQL 分析围绕 `predictive_maintenance2020.ai4i2020` 展开，重点包括整体故障率、各产品类型故障率、各故障类型数量、刀具磨损区间故障率、扭矩区间故障率、转速区间故障率、故障与正常样本均值对比，以及 `Type + wear_group` 和 `torque_group + speed_group` 的高风险组合分析。

SQL 在本项目中的价值是沉淀固定口径：pandas 更适合灵活探索和图表分析，而 SQL 更适合形成可重复执行、可审计、可移植的统计查询。后续在 notebook 中展示 SQL 结果时，可以直接引用 `03_basic_analysis.sql` 中的分析口径，避免每次临时重写统计逻辑。

Day 5 最值得同步到 notebook 或报告中的结果包括：整体故障率仍应与 pandas 侧约 3.39% 保持一致；产品类型故障率应继续关注 `L` 类型相对更高的现象；高刀具磨损区间、较高扭矩区间、较低转速区间以及它们的组合，是后续预测性维护分析中值得重点跟踪的风险信号。
